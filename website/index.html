Welcher Mod-Loader passt zu dir?

Die Entscheidung am Anfang bestimmt dein Tooling, deine Mappings und deine Community. Drei ernsthafte Optionen — hier ohne Lagerkampf.

🧵

Fabric

Leichtgewichtig · schnelle Updates

Minimaler Loader, riesiges Mixin-Ökosystem. Neue Minecraft-Versionen sind oft am Release-Tag schon nutzbar. Ideal für Client-Mods, Performance und Experimente.

  • Yarn oder Mojmap
  • Fabric API als Baukasten
  • Sehr kurze Build-Zeiten
⚒️

NeoForge

Batteriebetrieben · Event-getrieben

Der Forge-Nachfolger mit aufgeräumter API. Capabilities, Registries und ein starkes Event-System nehmen dir viel Boilerplate ab — perfekt für große Content- und Tech-Mods.

  • Offizielle Mojang-Mappings
  • Datapack-Registries first-class
  • Riesiger Modpack-Markt
🏛️

Forge (Legacy)

Ältere Versionen · 1.12–1.20

Immer noch die Heimat der Klassiker-Packs. Wenn dein Ziel 1.12.2 oder 1.16.5 heißt, führt kaum ein Weg daran vorbei — nur die Toolchain ist spürbar älter.

  • Maximale Mod-Kompatibilität
  • Bewährte Dokumentation
  • Langsamerer Versionszyklus

Zum Mitschreiben

Echter Code, keine Pseudo-Snippets

Alles hier läuft gegen aktuelle Mappings. Tab wechseln und den Unterschied zwischen Registry, Mixin und Datagen direkt sehen. 

package dev.blockforge.tutorial.item;

import net.minecraft.item.Item;
import net.minecraft.registry.Registries;
import net.minecraft.registry.Registry;
import net.minecraft.util.Identifier;

public final class ModItems {

    public static final Item RUBY = register("ruby",
            new Item(new Item.Settings().maxCount(64)));

    public static final Item RUBY_PICKAXE = register("ruby_pickaxe",
            new PickaxeItem(ModToolMaterials.RUBY, new Item.Settings()));

    private static Item register(String name, Item item) {
        Identifier id = Identifier.of(Tutorial.MOD_ID, name);
        return Registry.register(Registries.ITEM, id, item);
    }

    // Vom Mod-Initializer aufgerufen, damit die Klasse geladen wird.
    public static void init() {
        Tutorial.LOGGER.info("Registriere Items fuer {}", Tutorial.MOD_ID);
    }
}
package dev.blockforge.tutorial.mixin;

import dev.blockforge.tutorial.item.ModItems;
import net.minecraft.entity.effect.StatusEffectInstance;
import net.minecraft.entity.effect.StatusEffects;
import net.minecraft.entity.player.PlayerEntity;
import org.spongepowered.asm.mixin.Mixin;
import org.spongepowered.asm.mixin.injection.At;
import org.spongepowered.asm.mixin.injection.Inject;
import org.spongepowered.asm.mixin.injection.callback.CallbackInfo;

@Mixin(PlayerEntity.class)
public abstract class ExampleMixin {

    // Laeuft am Ende jedes Player-Ticks, ohne Vanilla zu ueberschreiben.
    @Inject(method = "tick", at = @At("TAIL"))
    private void blockforge$onTick(CallbackInfo ci) {
        PlayerEntity self = (PlayerEntity) (Object) this;
        if (self.getWorld().isClient()) return;

        if (self.getMainHandStack().isOf(ModItems.RUBY)) {
            self.addStatusEffect(new StatusEffectInstance(
                    StatusEffects.SPEED, 40, 0, true, false));
        }
    }
}
package dev.blockforge.tutorial.datagen;

import net.minecraft.data.server.recipe.RecipeExporter;
import net.minecraft.data.server.recipe.ShapedRecipeJsonBuilder;
import net.minecraft.recipe.book.RecipeCategory;

public class ModRecipeProvider extends FabricRecipeProvider {

    @Override
    public void generate(RecipeExporter exporter) {
        ShapedRecipeJsonBuilder
                .create(RecipeCategory.TOOLS, ModItems.RUBY_PICKAXE)
                .pattern("RRR")
                .pattern(" S ")
                .pattern(" S ")
                .input('R', ModItems.RUBY)
                .input('S', Items.STICK)
                .criterion(hasItem(ModItems.RUBY), conditionsFromItem(ModItems.RUBY))
                .offerTo(exporter);
    }
}

Häufige Fragen

Kurz beantwortet

Brauche ich Java-Vorkenntnisse?

Ein bisschen hilft enorm. Wenn du Klassen, Interfaces und Generics grob einordnen kannst, reicht das für den Einstieg — den Rest lernst du am Mod. Ganz ohne Programmiererfahrung solltest du erst zwei, drei Wochen reines Java machen.

Fabric oder NeoForge für den ersten Mod?

Fabric. Der Einstieg ist kleiner, die Build-Zeiten sind kürzer und du siehst schneller Ergebnisse. Die Konzepte — Registries, Events, Datagen — übertragen sich später fast eins zu eins.

Sind Mixins gefährlich?

Sie sind mächtig und deshalb leicht zu missbrauchen. Faustregel: Erst die offizielle API, dann Events, und nur wenn es wirklich keinen Hook gibt, ein Mixin — möglichst mit @Inject statt @Overwrite, damit andere Mods weiter funktionieren.

Darf ich meinen Mod verkaufen?

Nein. Mojangs EULA verbietet den Verkauf von Mods. Spenden, Ko-fi oder Werbeeinnahmen über Modrinth sind dagegen üblich und erlaubt.
